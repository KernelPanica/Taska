# Checkpoint 4 — Связи, вложенность и прогресс

Реализован для приёмки. Демонстрация команде ещё не проводилась.

- [x] Единый блок связей на странице задачи; поиск по ID или части названия.
- [x] Обычная связь, блокирует / заблокирована, родитель / дочерняя задача.
- [x] Изменение типа существующей связи без удаления её записи.
- [x] Удаление связи сохраняет обе задачи.
- [x] Карточка связи показывает ID, название, проект, статус, исполнителей и теги.
- [x] Переход по карточке к связанной задаче.
- [x] Вложенность не привязана к типу; глубина не ограничена числом уровней.
- [x] Запрет самоссылок, циклов, повторных связей и второго родителя.
- [x] Родитель показывает долю завершённых непосредственных дочерних задач.
- [x] Bug/Request имеют только бинарный прогресс; без источника прогресс не выводится.
- [x] Проверки прав, конфликтов, сохранения и русского интерфейса.

## Сценарий приёмки

1. Как PM создать четыре задачи разных типов.
2. В первой открыть «Связи задач → Добавить связь», найти вторую по ID,
   выбрать «Родитель задачи». Повторить для второй/третьей и третьей/четвёртой.
3. В дочерней задаче проверить обратную связь и перейти по ней к родителю.
4. Попытаться сделать четвёртую родителем первой: получить ошибку без изменений.
5. Добавить ещё одну дочернюю задачу к первой. Завершить одну из двух дочерних:
   родитель должен показать 1 / 2, 50%. Задачи не завершаются автоматически.
6. Изменить связь на «Блокирует», проверить обе стороны, затем удалить её:
   обе задачи должны остаться доступны.
7. Создать связь между проектами, где пользователь PM в обоих. Участник только
   одного проекта не должен видеть закрытую задачу или её вклад в прогресс.
8. Повторить редактирование связи из двух вкладок: устаревшее изменение отклоняется.

## Правила и границы

Связи изменяют PM/admin с правами в обоих проектах. Участники видят только связи,
для которых доступны обе задачи. Если хотя бы одна дочерняя задача недоступна,
общий прогресс скрывается, чтобы не раскрывать её наличие через счётчик.

У задачи один родитель; между парой задач одна изменяемая связь. В списке тип
указывается относительно открытой задачи: «Родитель задачи» означает, что текущая
задача — родитель выбранной. Обычная связь симметрична; блокировка и иерархия
показывают обратные названия на другой стороне.

Доли дочерних задач равные, без учёта оценки. Готовность означает категорию статуса
«завершённый». Проверка checklist для Story опциональна в roadmap и пока не добавлена.
Имена базовых типов Bug/Request определяют бинарный режим.

Серверная проверка циклов использует итеративный обход графа. В текущем SQLite
первый запрос записи сериализует проверку и сохранение; переход на другую СУБД
потребует отдельной проверки блокировок графа. Миграция 0010 добавляет таблицу
связей и ограничения, не меняя существующие задачи.
