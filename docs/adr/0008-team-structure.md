# 0008. Оргструктура, пространства и измерения

- Статус: принято, 2026-11-16; сверено с «YourSpace — требования» от 16.11.2026. Раздел «Люди» заменён [0009](0009-catalog-people.md): люди приходят из каталога YourSpace
- Требования: R-2.14 (измерения), R-2.15 (оргструктура), R-2.16 (пространства), R-2.2 (каталог людей); карточка YT-02. Смежные: YT-03 (люди из общего каталога), YT-08 (права), YT-19 (логика нормы WIP), YT-21 (шаблоны пространств)

## Контекст

Нужна основа для фильтров, досок и прав: кто в каких колодцах и фичекомандах, кто лид и ПМ.
По R-2.2 людей ведёт общий каталог YourWiki, а колодцы, команды, лид, ПМ и личная норма WIP — YourTask. Каталог подключается в YT-03, а до тех пор людей заводит суперадмин здесь (YT-02).

## Решение

**Термины в коде — по глоссарию** (раздел 1): колодец — `guild`, фичекоманда — `feature team`, суперадмин — `superadmin`, пространство — `space`, измерение — `dimension`.

**Люди.** Человек — строка `users`, та же, что у пользователя YourTask. Суперадмин заводит человека заранее (`yourspace_subject` пустой). При первом входе через YourSpace человек связывается с аккаунтом по подтверждённому email.
После связывания email ведёт YourSpace: правка в карточке запрещена, при входе email синхронизируется. Имя пока ведётся здесь и при входе не перетирается. Почта уникальна; если при входе она занята другим человеком, вход отклоняется с кодом `account_conflict`.
Карточка (YT-02): имя, почта, язык, колодцы, фичекоманды, личная норма WIP (`wip_limit`, 0…1000 или пусто; как она работает — YT-19).
С YT-03 имя и почта станут данными каталога «только для показа» (R-2.15, п. 4). Заведённые здесь люди сопоставятся с каталогом по аккаунту YourSpace (`yourspace_subject`).

**Колодцы и фичекоманды** (R-2.15) — два разных справочника групп одинакового устройства: название (уникальное), состав, «глава». У колодца лид (`lead_id`), у фичекоманды ПМ (`pm_id`).
Глава — поле в карточке группы, а не роль в аккаунте: сменили лида — права переедут сами, когда появятся (YT-08). Глава не обязан входить в состав.
Человек состоит в 0…n колодцах и 0…n командах. Состав меняется из карточки группы и из карточки человека (полная замена набора). Код общий — `GroupKind` в `apps/api/src/directory/groups.ts`.

**Пространства** (R-2.16). Суперадмин создаёт и переименовывает; адрес (slug) получается транслитерацией названия и при переименовании не меняется. Стартовые «Дирекция», «Core», «Инфраструктура», «Производство» создаёт миграция `0001` — они есть в любой установке.
Сейчас участник видит пространства, где состоит, суперадмин — все. Кто видит «Core», «Инфраструктуру» и «Производство», а «Дирекцию» — только участники дирекции, настраивается правами в YT-08. Создание из шаблона — YT-21.

**Измерения** (R-2.14). Два вида:

- «группа людей» — значения из справочника-источника: фичекоманды или колодцы;
- «список» — значения задаёт админ (локация, акт и т. п.); они упорядочены и уникальны без учёта регистра.

Множественный выбор включается в настройках измерения. Тип и источник после создания не меняются (на них опираются значения тикетов). Название, режим выбора и значения списка менять можно; id значения с тем же текстом сохраняется.
Стартовые системные, создаёт миграция, удалить нельзя:

- «Фичекоманда» (`team`) — группа людей из фичекоманд, одно значение или пусто;
- «Стрим» (`stream`) — группа людей из колодцев, несколько значений.

Измерения общие для установки: доски фильтруют по ним через пространства (R-2.18: `stream = GD`). Теги (R-2.14, п. 2) — отдельная сущность, YT-22.

**Кто ведёт.** Читать справочники может любой вошедший; менять — только суперадмин (роль `superadmin` со второй проверкой входа, ADR 0003). Выдача этих прав другим — YT-08.

**Миграции, пересобирающие таблицы.** SQLite меняет ограничения столбцов только пересборкой таблицы. Раннер миграций выключает внешние ключи на время миграций (иначе `DROP TABLE users` каскадом удалил бы сессии), а после проверяет `PRAGMA foreign_key_check`. Тест апгрейда со схемы YT-01 проверяет, что сессии и участие в пространствах сохраняются. Роль `admin` из схемы YT-01 переименована в `superadmin` той же миграцией.

## Последствия

- Отображаемые имена системных измерений хранятся данными («Фичекоманда», «Стрим») и в английском интерфейсе показываются как есть. Если нужен перевод, подставлять по `key` в YT-04 вместе с системными полями.
- При подключении каталога (YT-03) ручное заведение людей станет сопоставлением с каталогом; модель `users` для этого готова.
