# 0002. Модульный монолит: Fastify + SQLite + React

- Статус: принято, 2026-11-16
- Требования: карточка, п. 1 и цель 1 («новый разработчик запускает проект за один шаг»); R-3.1, R-3.2, R-3.5, R-3.6 — сверить

## Контекст

Нужен пустой, но устойчивый каркас, который новый разработчик запускает одной командой на чистой машине, без ручной настройки БД.
В репозитории уже был TypeScript-монорепозиторий Taska на том же стеке; его домен (задачи, спринты, плагины) убран, инфраструктура переиспользована.

## Решение

- **Один процесс Node 24** (Fastify 5) отдаёт API и собранный React-интерфейс. Монорепозиторий npm workspaces:
  `packages/contracts` (общие типы API), `apps/api`, `apps/web`.
- **SQLite** (better-sqlite3, WAL, внешние ключи) — без внешних сервисов; файл БД в `data/` (локально) или томе `/data` (Docker).
- **Версионированные миграции** — SQL-файлы в `apps/api/drizzle` с журналом Drizzle. Применяются при каждом старте; уже применённые пропускаются, поэтому повторный запуск ничего не меняет (проверяется тестом и в CI).
- **Профили конфигурации** (`apps/api/src/config.ts`):
  - `development` — всё по умолчанию: БД `data/yourtask.db`, секрет создаётся и сохраняется в `data/.secret-key`, заглушка YourSpace, тестовые данные, сервер слушает только 127.0.0.1;
  - `test` — БД в памяти, фиксированный секрет, заглушка YourSpace, тестовые данные, без логов;
  - `production` — секрет, адрес и OIDC-настройки обязательны; заглушка и тестовые данные запрещены (приложение не стартует).
- Запуск: `npm install && npm run dev` или `docker compose up --build`.

## Последствия

- Горизонтальное масштабирование ядра не предусмотрено; при необходимости — отдельный ADR о переходе на PostgreSQL (Drizzle это допускает).
- Схема меняется только новой миграцией; правка применённой миграции запрещена.
