# 0012. Тикет: ключ, поля, люди, статус, архив, параллельные правки

- Статус: принято, 2026-11-17
- Требования: R-2.6 (ключ), R-2.7 (смена типа), R-2.10 (статусы, отмена), R-2.11 (архив), R-3.1 (параллельные правки), R-3.2 (безопасный Markdown), R-3.3 (интерфейс); карточка YT-06

## Решение

**Ключ.** Формат `AOS-N`: один сквозной счётчик на всю систему (`ticket_counter`), номер выдаётся в той же транзакции, что и вставка тикета.

- Префикс задаётся при установке: `YOURTASK_KEY_PREFIX`, по умолчанию `AOS`.
- Ключ не меняется при смене типа и пространства и не переиспользуется: тикеты не удаляются. Корзина и окончательное удаление — YT-14, и там номер тоже не возвращается.
- Тест проверяет, что номера идут подряд в разных пространствах, а неудачное создание и отмена номер не расходуют и не освобождают.

**Тикет** (`tickets`) хранит:

- пространство, тип, статус, исход, название;
- описание в Markdown и чеклист — JSON с самостоятельными пунктами; пункты-ссылки на детей — YT-10;
- значения полей типа по системному имени — команда и стрим, оценки и свои поля;
- приоритет, теги, даты начала и окончания, флаг «заблокировано» с обязательной причиной;
- причину отмены, архив с причиной;
- версию, автора и время.

Теги пока строки; отдельной сущностью они станут в YT-22.

**Люди** (`ticket_people`): несколько исполнителей, заказчик, тестировщик, наблюдатели. Один человек может быть в нескольких ролях. Назначать можно только активных людей из каталога (ADR 0009). «Назначить на себя» добавляет себя к исполнителям.

**Поля.** Значения проверяются по виду поля, как в шаблонах (ADR 0010). Проверяются только присланные значения. Значения полей, которых больше нет в типе, хранятся и скрываются, а не стираются (R-2.7). `null` очищает значение.

**Создание.** Тикет создаётся одной строкой («название + тип») или по шаблону. Шаблон подставляет структуру описания, чеклист и значения полей. Начальный статус — первый в схеме.

**Статус** — только через действия с правилами YT-05 (ADR 0011):

- `transition` проверяет строгий порядок и обязательное на входе. При нарушении — `422 transition_blocked` со списком того, что заполнить; интерфейс показывает список человеческим языком. Завершённому статусу нужен исход.
- `cancel` работает из любого статуса: «отменено» и обязательная причина.
- `archive` и `unarchive`: архив — признак с причиной («выполнено», «отложено», «не размечено»), а не статус. Статус сохраняется, архив скрыт из выборок по умолчанию (`archived=exclude|include|only`).
- `change-type` переносит статус по имени, иначе по категории. Если вариантов несколько — `409 status_choice_required` с `candidates`, интерфейс просит выбрать.

**Параллельные правки (R-3.1).** Каждое изменение несёт `version`. Устаревшая версия не сохраняется: ответ `409 version_conflict`, в Problem Details расширение `current` с актуальным тикетом.

- Интерфейс сразу показывает актуальное состояние и сообщение «Пока вы правили, тикет изменил(а) Имя: изменились поля …». Черновик формы при этом остаётся, его можно проверить и сохранить снова.
- Свойства в форме подтягивают чужие изменения, только пока человек сам ничего не правит.
- «Редактирует Имя» в реальном времени — позже, вместе с обновлениями без перезагрузки.

**Markdown.** Описание хранится как есть, а показывается компонентом, который строит элементы React и не вставляет HTML.

- Поддерживаются заголовки, списки, абзацы, **жирный** и ссылки только на `http(s)`.
- `<script>` показывается текстом, `javascript:`-ссылка остаётся текстом.
- Некорректная разметка не ломает страницу. Это проверено тестами интерфейса.

**Интерфейс.**

- Список тикетов — на странице пространства: быстрое создание и создание по шаблону.
- Карточка в списке открывается кликом по любой свободной части. С клавиатуры — по ссылке в названии (R-3.3).
- Название и описание правятся явной кнопкой, у описания — живой предпросмотр. Отметка в чеклисте сохраняется сразу и показывается до ответа сервера. Свойства — явной кнопкой «Сохранить».
- Длинные название и описание переносятся и не ломают раскладку.

**Права.** Видят и правят тикеты участники пространства и суперадмин. Тестовые тикеты видят только тестовые пользователи (ADR 0006). Профили прав — YT-08.

## Последствия

- История изменений и комментарии — YT-07: сейчас видно только, кто создал и кто менял последним.
- Обновления без перезагрузки пока нет: чужие правки видны после перезагрузки или при попытке сохранить (конфликт).
