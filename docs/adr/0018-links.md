# 0018. Связи между тикетами и блок ссылок с документами YourWiki

- Статус: принято, 2026-11-19
- Требования: R-2.13 (связи), R-2.17 (связи между пространствами), R-2.24 (ссылки), R-2.40 (YourWiki через API), R-2.12 (баги «вызывает» не в прогрессе), R-3.2 (безопасность); карточка YT-12. Зависит от WK-02 «API состояния документа для YourTask»

## Решение

**Типы связей** — таблица `link_types`.

- Системные типы R-2.13: «связан с», «блокирует», «дублирует», «клонирован из», «вызывает».
- Админ добавляет свои типы (`/api/v1/link-types`).
- У типа два названия, по одному на каждую сторону: «блокирует» у одного тикета, «заблокирован» у другого. Симметричный тип читается одинаково с обеих сторон.
- Родитель и ребёнок — это иерархия (ADR 0015), а не связь, но добавляются из той же формы «Добавить связь или родителя».

**Связь** — одна строка `ticket_links` (тип, откуда, куда), видна с обеих сторон.

- Смена типа — одно действие (`PATCH /links/{id}`), направление можно развернуть.
- Удаление связи тикеты не трогает.
- Повтор той же связи даёт `409 link_exists`.
- Связи между пространствами работают так же. Недоступный зрителю тикет показывается строкой «Связанный тикет недоступен», без ключа и названия — в карточке, в журнале и в API.

**Права.** Добавить связь — нужна правка своего тикета, а второй тикет должен быть виден зрителю. Иначе 404, как будто тикета нет. Менять и удалять связь — нужна правка хотя бы одной стороны.

**История.** Каждая связь, смена её типа и удаление пишутся в журнал обеих сторон: «Блокирует: AOS-5 …».

**Баг «вызван» стори.** Баг связью не становится ребёнком. Свёртки родителя не учитывают детей, связанных с ним через «вызывает» (R-2.12), даже если такой баг всё же сделали ребёнком.

**Блок ссылок** — таблица `ticket_web_links`.

- **Обычный адрес.** Сервер сам получает заголовок страницы: `og:title` или `<title>`. Защита от SSRF:
  - только http(s);
  - без адресов внутренней сети (кроме разработки, `YOURTASK_LINK_PREVIEW_PRIVATE`);
  - до 3 переадресаций, каждая проверяется заново;
  - 3 секунды и 256 КБ на ответ.

  Не получилось — ссылка сохраняется без заголовка.

- **Адрес YourWiki** (`{YourWiki}/documents/{id}`) становится документом. Название документа не хранится: его показывают живым и только тем, кому YourWiki его открыл.

**YourWiki через WK-02.** Контракт взят из кода WK-02 в репозитории yourwiki (`apps/server/src/integrations`). На 2026-11-19 он лежит в локальном stash и в main не влит.

- **Запросы:**
  - `GET /api/integrations/documents/{id}` и `/resolve?url=` → метаданные: название, состояние `available` / `trashed` / `deleted` / `unavailable`, доступ `read` / `write` / `none`, источник, оригинал, `canRequestAccess`;
  - `POST /api/integrations/documents/access-requests { url, message }` — запрос доступа.
- **Авторизация** — токен доступа YourSpace самого человека: YourWiki сверяет его через `userinfo` YourSpace.
  - Поэтому YourTask сохраняет токен доступа из входа OIDC в сессии, зашифрованным AES-256-GCM ключом от секрета сервера.
  - YourWiki вызывается от имени того, кто вошёл: под «Смотреть как» права в YourWiki не подменяются.
  - Нет токена или он истёк — ссылка помечается «Войдите заново, чтобы видеть документы». Карточка при этом работает.
- **Что видит человек:**
  - живое название;
  - «доступ есть» или «нет доступа»;
  - «в корзине» или «удалён»;
  - «Открыть оригинал» — только при проверенном доступе в исходном сервисе (например, Google Диск), и ссылка ведёт туда;
  - «Запросить» — запрос уходит в YourWiki. Сам факт запроса YourTask запоминает у себя, потому что WK-02 его не возвращает.
- **Права не синхронизируются.**
- YourWiki не ответил — ссылка помечается, карточка работает.

**Упоминания в описании.** Через @ — человек, связанный тикет или документ из блока ссылок; документ вставляется ссылкой Markdown. В описании ссылка на документ показывает живое название. Без доступа — «Документ YourWiki», без названия и без ссылки.

**Заглушка YourWiki для разработки** (`/dev/yourwiki`, `YOURTASK_YOURWIKI_MODE=dev`).

- Отвечает так же, как WK-02, по тем же путям.
- Узнаёт человека по токену, который выдала заглушка YourSpace.
- На её странице «админ YourWiki» переименовывает документы, кладёт в корзину, выдаёт доступ и видит запросы.
- В production запрещена.

## Последствия

- **Предупреждение о расхождении доступов** («тикет скрыт, а документ открыт» и наоборот) требует знать, кому открыт документ. WK-02 этого пока не отдаёт. Клиент читает необязательное поле `audience: "everyone" | "restricted"`: в заглушке оно есть, и предупреждение работает. **Предложение к WK-02:** добавить `audience` в метаданные документа.
- **Человек без доступа** по WK-02 получает документ без названия (`unavailable`). На макете название видно, но мы следуем WK-02: название закрытого документа не раскрывается.
- **Документ по адресу Google Диска** WK-02 тоже распознаёт через `resolve`. В YourTask такие адреса пока считаются внешними ссылками: связь с YourWiki — только по адресу YourWiki.
- **Срок токена YourSpace.** Он истекает вместе с токеном доступа (по `expires_in`); обновления по refresh-токену пока нет. Человек видит «Войдите заново».
- **Клонирование и слияние дублей** (R-2.23) будут ставить связи «клонирован из» и «дублирует» автоматически — карточкой про клоны и дубли.
