# 0022. Доски: фильтр TQL, дерево зон, перенос с выбором статуса, живые изменения

- Статус: принято, 2026-11-21
- Требования: R-2.18 (доски), R-2.19 (зоны), R-5.1 (стартовое дерево зон), R-2.11 (завершённые старше N дней), R-2.21 (WIP на зоне), R-3.3 (интерфейс), R-3.4 (доска до 500 карточек ≤ 2 с), R-2.20 (права); карточка YT-16

## Решение

**Доска — одна сущность: фильтр TQL, владелец и раскладка.** Отдельных «видов» нет. Таблица `boards` хранит:

- название и фильтр (тот же разборщик, что у поиска, ADR 0021; сломанный запрос не сохраняется);
- владельца: пространство (`space_id`) или человека (`owner_id`);
- раскладку: дорожки (`none`, `parent`, `team`, `stream`, `assignee`), порядок в колонке (`due`, `priority`, `manual`), срок для завершённых (`done_days`, по умолчанию 14), чипы (`type`, `stream`, `team`);
- дерево зон — JSON на доске.

Тикеты доска не хранит. Карточки — выборка `tql.match` глазами зрителя: права и маска полей проверяются для каждого тикета. «Только заголовок» на доску не попадает: у такой карточки нет статуса. Доска Жаб (`team = Frogs or involvedTeams = Frogs`) и доска лида ГД (`stream = GD or assignee.guild = GD`) — две строки одной таблицы; общий тикет на обеих — один и тот же.

**«Мои задачи» есть у каждого.** Личная доска `kind = 'mine'` с фильтром `assignee = me() and statusCategory != done` создаётся при первом обращении к списку досок. Удалить её нельзя. Позже на ней появятся личный баннер перегруза (YT-19) и блок доработки (YT-23).

**Права.**

- Личную доску видит и меняет только владелец.
- Доску пространства видит каждый, кто видит пространство. Менять её — право «Настраивать доски пространства» (`boards_space`).
- Перенос карточки — право «Менять статус» на тикет. Карточка без этого права не перетаскивается, на ней замок с подписью.

**Зоны.**

- Зона объединяет статусы разных типов по имени статуса. Тип без статусов зоны проходит её насквозь.
- Дерево любой глубины. Стартовое — R-5.1: Discovery / Delivery / Done → Бэклог … Готово.
- Владелец доски перестраивает дерево у себя: `PUT /boards/:id/zones`. Статус — только в одной зоне; цикл и неизвестный родитель — ошибка 400.
- Статус без зоны попадает в служебную колонку «Не сопоставлено» с предупреждением текстом и значком. Карточки не пропадают.
- WIP-лимит вешается на зону любого уровня. Счётчик «4 / 3» считает карточки в работе без признака «ожидание», каждую один раз. При превышении заголовок красный и подписан «WIP превышен».
- Дерево зон пространства и шаблоны досок — следующий шаг. Сейчас стартовое дерево копируется в каждую новую доску.

**Шапка и детализация — общая функция `boardLayout` в contracts.** По дереву, детализации 1 / 2 / 3, свёрнутым зонам и скрытым уровням она строит строки шапки (сетка с `colSpan`/`rowSpan`) и колонки:

- детализация N раскрывает зоны до уровня N;
- лист-зона из нескольких статусов на следующем уровне делится на колонки-статусы;
- свёрнутая зона — одна колонка;
- скрытый уровень убирает строку шапки, колонки остаются.

Детализация, свёрнутые зоны и уровни, плотность, выключенные чипы, своя раскладка дорожек и свёрнутые дорожки — личные настройки (`board_prefs`), у других доска не меняется. Они же записаны в адрес (`?detail=&collapsed=&hide=&density=&lanes=&off=`): по ссылке другой видит то же в пределах своих прав, его собственные настройки при этом не перезаписываются.

**Перенос — `POST /boards/:id/move`.** Сервер находит статусы зоны (вместе с подзонами), доступные схеме типа карточки:

- нет таких — `422 zone_not_for_type` с причиной: «у бага нет статусов зоны „Проработка“, тип проходит её насквозь»;
- один — переход сразу;
- несколько и статус не выбран — `409 status_choice_required` с вариантами;
- выбранный — обычный переход тикета: проверка версии (конфликт не затирается молча), условия входа статуса, исход для завершённого.

Интерфейс знает схемы карточек на доске и спрашивает заранее, на месте броска: всплывающий выбор, не модальное окно. Esc и клик мимо закрывают, стрелки ходят по вариантам. Колонка без статусов для типа при перетаскивании заштрихована и подписана «нет статусов для „Баг“»; бросок в неё объясняет причину. Перетаскивается вся карточка; с клавиатуры то же делает кнопка «Переместить» на карточке. После броска карточка сразу на новом месте, ошибка откатывает её и объясняет, что заполнить, теми же словами, что карточка тикета.

**Ручной порядок** — `board_ranks` (доска × тикет × ранг), общий для всех зрителей доски. Клиент присылает новый порядок колонки, сервер пишет ранги. Порядок в дереве не меняется.

**Дорожки** — по родителю, фичекоманде, стриму или исполнителю. Без значения — «Без …» в конце. Карточка с несколькими родителями стоит в каждой дорожке; вторая и следующие помечены «тот же тикет», в счётчиках и WIP — один раз. Недоступный родитель — «Связанный тикет недоступен».

**Карточка** (R-2.18): ключ, номер в потоке, название, тип, стрим, исполнитель, точный статус внутри зоны, срок и просрочка. Просрочка — значок, слово «просрочено» и полоса слева, не только цвет. Плотности:

- компактная — без строки тегов, название в одну строку;
- обычная — плюс несколько родителей;
- подробная — плюс команда, теги, приоритет, прогресс.

**Завершённые старше N дней скрыты** без архивации (по `status_changed_at`), сколько скрыто — подписано. Архив скрыт, как во всех выборках. Больше 1000 карточек доска не рисует и просит сузить фильтр.

**Живые изменения — Server-Sent Events, `GET /api/v1/events`.**

- Любое удачное изменение через API (кроме входа и личных настроек) публикует в шине процесса событие «тикеты поменялись».
- В событии нет данных тикета, поэтому права не утекают: открытые доски перечитываются через API, несколько событий подряд — одно перечитывание.
- EventSource сам переподключается. Остановка сервера закрывает открытые потоки.
- Шина живёт в процессе: несколько экземпляров сервера потребуют общей шины (например, через базу или Redis) — сейчас экземпляр один.

**«Создать» на доске** создаёт тикет в пространстве доски. Команду, стрим и «исполнитель — я» он берёт из условий фильтра «поле = значение» (для `or` — из первой ветки), поэтому карточка сразу на доске. Если всё же не подходит под фильтр — так и сказано, со ссылкой на тикет.

## Скорость (R-3.4)

`apps/api/tests/boards-load.test.ts`: 100 000 тикетов, доска Жаб с 500 карточками в работе, дорожки по родителю, глазами участницы — около 110–130 мс от запроса до ответа при потолке 2 с.

## Не входит

- Панель загрузки участников и баннеры перегруза (макет 01) — YT-19.
- Режимы WIP «запрет» — R-2.21, вместе с перегрузом.
- «Смотреть как» и «Режим показа» на доске работают как везде (ADR 0014). Гант — YourDash. Таблица — после MVP.
- Шаблоны досок и закреплённые ссылки (ГДД, ТехГДД) — отдельно.
