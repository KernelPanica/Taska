# 0020. Корзина: удаление со «Отменить», вопрос про детей, след родителя и пересвязка

- Статус: принято, 2026-11-19
- Требования: R-2.22 (удаление и корзина), R-2.8 (удаление родителя, след), R-5.2 (права «Удалять в корзину», «Восстанавливать», «Окончательно удалять»), R-2.27 (уведомление ПМа), R-2.6 (ключ не переиспользуется), R-2.25 (неизменяемая история), R-3.1, R-3.2; карточка YT-14

## Решение

**Удалённый тикет остаётся строкой с признаком** `deleted_at` / `deleted_by` / `trash_batch_id`.

- Ключ не освобождается: счётчик `ticket_counter` только растёт, поэтому ключ не выдаётся снова и после очистки (R-2.6).
- История тикета неизменяема (триггеры R-2.25) и остаётся.
- Удалённые исключены из выборок: список, дерево, номера в потоке, поиск. Ссылка на удалённый тикет отвечает `404 ticket_in_trash` с ключом, названием, кто и когда удалил и может ли зритель вернуть. Очищенный отвечает `410 ticket_purged`. Тот, кто тикет не видел бы, получает обычный `404` (R-2.17).

**Связи удалённого снимаются в той же транзакции и запоминаются** в `trash_relations`:

- родители и дети с позицией;
- связи R-2.13 со стороной;
- пункты-дети в чеклистах живых родителей.

Поэтому дерево, свёртки, номера и права остальных тикетов сразу верны, без фильтров «кроме удалённых» в каждой формуле. Каждая снятая связь пишется в историю второй стороны с пометкой `trash`. У ребёнка это строка «Родитель AOS-199 Прототип боя удалён, связь снята, след сохранён».

**Удаление — без окна подтверждения** (`POST /tickets/trash`).

- После удаления на любой странице 15 секунд видна плашка «AOS-199 в корзине · Отменить».
- Одно действие — один пакет (`trash_batches`). «Отменить» — это `POST /trash/restore {batchId}`.
- Больше одного тикета (выделение в дереве или «удалить вместе с детьми») — `409 bulk_confirm_required` с числом. Интерфейс просит подтвердить и повторяет запрос с `confirm: true`. Нужны права «Удалять» на каждый тикет и «Массовые операции».

**Удаление родителя** при детях вне удаляемого набора возвращает `409 children_choice_required` со списком детей. Интерфейс показывает диалог из четырёх вариантов R-2.8:

| Вариант               | Что делает                                                                             |
| --------------------- | -------------------------------------------------------------------------------------- |
| `keep` (по умолчанию) | Оставить без этой связи.                                                               |
| `relink`              | К другому родителю по ключу или к новому: создаётся тикет того же типа и пространства. |
| `grandparent`         | К родителям удаляемого.                                                                |
| `delete`              | Вместе с ним: вся ветка одним пакетом.                                                 |

Для `relink` и `grandparent` нужно право «Перемещать» на детей. Новые связи пишутся в `trash_added_links`: «Отменить» их снимает и возвращает детей на место.

**След родителя** (`parent_traces`) появляется у каждого ребёнка удалённого родителя при любом варианте и хранится навсегда:

- В следе — копия ключа и названия, поэтому он переживает очистку.
- Карточка ребёнка показывает следы, по которым ребёнок ещё не привязан заново: «AOS-199 «Прототип боя» · удалён 02.11 · ещё тикетов с этим следом: 6».
- `parentTrace(AOS-199)` в поиске списка тикетов находит всех бывших детей, включая уже привязанных заново.
- «Связать заново» (`POST /traces/relink {parentKey, toKey?}`) привязывает всех бывших детей одним действием к новому родителю. Без `toKey` — к самому родителю, если его восстановили.
- Кого зритель не может перемещать или кого не пускают правила дерева, тот пропускается и называется в ответе.

**Восстановление** (`POST /trash/restore` по ключам или пакету):

- Возвращает связи, у которых вторая сторона жива.
- Связь, ставшая циклом или нарушающая подчинение, пропускается и называется в ответе (`skipped`). Остальное восстанавливается.
- Следы детей, снова привязанных к восстановленному родителю, закрываются.
- Восстанавливают удаливший, ПМ команды и админы, по R-5.2. Область `own_deleted` сравнивает `deleted_by` со зрителем.

**Права** — из матрицы R-5.2 (YT-08):

| Право                | Кто               | Объём                       |
| -------------------- | ----------------- | --------------------------- |
| Удалять в корзину    | Участник          | Свои тикеты, пока в очереди |
|                      | Лид колодца       | Свой стрим                  |
|                      | ПМ                | Своя команда                |
|                      | Админ             | Всё                         |
| Восстанавливать      | Удаливший         | Удалённое им самим          |
|                      | ПМ                | Своя команда                |
|                      | Админ             | Всё                         |
| Окончательно удалять | Только суперадмин | —                           |

Кнопки в интерфейсе — подсказка; решает сервер.

**Уведомление ПМа** (R-2.27): если лид колодца удалил тикеты команды своего стрима, ПМ этой команды получает в колокольчике одно сообщение на пакет. Колокольчик сделан минимально: таблица `notifications`, `GET /notifications`, `POST /notifications/read`. Другие события и группировка R-2.27 — в карточке уведомлений.

**Очистка** — системное правило.

- Раз в `YOURTASK_TRASH_SWEEP_MINUTES` (по умолчанию 60) сервер очищает всё, что пролежало дольше срока. Срок по умолчанию 90 дней («раз в квартал»), суперадмин меняет его в «Корзине» без перезапуска.
- Досрочно очищает только суперадмин (`POST /trash/purge`), с подтверждением в строке.
- Очистка стирает:
  - описание, чеклист, значения полей, теги;
  - людей;
  - вложения (файлы с диска);
  - блок ссылок;
  - тексты комментариев.
- Остаются ключ, название (как в следах детей), следы и история.
- Удаление, восстановление и очистка пишутся в журнал безопасности (R-3.2).

## Почему так

- Признак вместо переноса в отдельную таблицу: ключ, история, комментарии и вложения ссылаются на `tickets.id`, а восстановление — это одна строка `UPDATE`.
- Снимать связи вместо того, чтобы фильтровать удалённых: дерево, свёртки, номера, права и охват уже работают через `ticket_parents`, `ticket_closure` и `ticket_links`. Фильтр пришлось бы добавить в каждую формулу, и любая забытая дала бы ошибку в прогрессе или правах.
- Отдельная таблица следов, а не только история: по следу нужно искать (`parentTrace`) и действовать («Связать заново»), а из журнала этого не сделать.

## Ограничения

- TQL (R-2.28) ещё нет. `parentTrace(AOS-N)` пока понимает только поле поиска списка тикетов (`q`). Когда появится разборщик TQL, функция подключится к той же таблице следов.
- Выдача прав на ветку (`branch`) работает через замыкание дерева. У удалённого тикета связей нет, поэтому право, полученное только через ветку, на время корзины не действует. Восстанавливают его удаливший, ПМ команды и админы пространства.
- История очищенного тикета остаётся в базе: она неизменяема по R-2.25. Через API она недоступна, потому что тикет отвечает `410`.
- Резервная копия корзины — это резервная копия базы и каталога вложений (раздел 4). Очищенное из бэкапов не вычищается.
