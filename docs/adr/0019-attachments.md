# 0019. Вложения: лимиты админа, загрузка частями с докачкой, тип по содержимому, выдача через права

- Статус: принято, 2026-11-19
- Требования: R-2.24 (вложения), R-3.2 (безопасность), R-3.3 (понятные ошибки), раздел 4 (хранилище от 500 ГБ, резервные копии); карточка YT-13

## Решение

**Хранение.**

- Файлы лежат в каталоге `YOURTASK_ATTACHMENTS_PATH`: по умолчанию `attachments` рядом с базой, в контейнере — `/data/attachments`. Каталог вне публичного каталога веба.
- Имена на диске случайные (`files/ab/<uuid>`); имя для показа очищено: без путей и управляющих символов, не длиннее 200 знаков.
- В базе: тикет, имя, тип, MIME, размер, SHA-256, автор.
- Сервер файлы не исполняет: выдаёт их как поток байт.

**Лимиты и типы** задаёт суперадмин в «Настройке тикетов → Вложения»: на файл, на тикет, на пространство и список разрешённых типов.

- Хранятся в базе и читаются при каждой загрузке, поэтому меняются без перезапуска.
- По умолчанию: файл до 500 МБ (записи багов), тикет до 2 ГБ, пространство до 100 ГБ.
- SVG и HTML не поддерживаются вовсе: в них может быть скрипт.

**Проверка до начала загрузки, без 413 и таймаутов.**

- Одни и те же правила (`checkUpload` в contracts) проверяет интерфейс — сразу при выборе файла, ещё до запроса — и сервер при открытии загрузки (`POST /tickets/{key}/uploads` с именем и размером). Ответ — `422 upload_refused` с причиной: тип, файл, тикет или пространство.
- Незавершённые загрузки резервируют место, поэтому две параллельные не превысят лимит.

**Загрузка частями с докачкой.**

- Файл идёт частями по 4 МБ: `PUT /uploads/{id}?offset=N`, тело `application/octet-stream`. Это меньше лимита тела запроса, поэтому 413 не бывает.
- После обрыва клиент спрашивает `GET /uploads/{id}`, сколько байт уже на сервере, и продолжает с этого места. Повтор с неверного места даёт `409` с правильной позицией.
- Клиент ждёт с нарастающей паузой до 8 неудачных попыток подряд на одну часть.
- Незавершённые загрузки старше суток удаляются.

**Тип по содержимому.**

- Первая часть сверяется с сигнатурами: PNG, JPEG, GIF, WebP, MP4/MOV (`ftyp`), WebM, PDF, zip-контейнеры Office, текст в UTF-8.
- Расширение должно совпасть с найденным типом, иначе `422 file_type_mismatch` — ещё до загрузки остального.
- Текст с `<script>`, `<html>`, `<svg>` или `<iframe>` текстом не считается.
- MIME при выдаче задаёт сервер по типу, а не по тому, что прислал браузер.

**Выдача.**

- `GET /api/v1/attachments/{id}` — только с доступом к содержимому тикета (ADR 0014). Чужой или скрытый тикет — 404, «только заголовок» — 403, без входа — 401.
- Заголовки:
  - `X-Content-Type-Options: nosniff`;
  - `Content-Security-Policy: sandbox`;
  - `Content-Disposition`: `inline` только для изображений, видео и PDF, остальное скачивается; имя в RFC 5987.
- `Range` поддерживается: видео играет и перематывается в карточке.

**Права.**

- Прикреплять — тому, кто может комментировать тикет: скриншот к комментарию — частое действие.
- Удалять — автору вложения или тому, кто правит тикет.
- Скачивать — всем, кому открыто содержимое.

**История.** Загрузка и удаление пишутся в журнал тикета: «Прикреплён файл …», «Удалён файл …».

**В интерфейсе.**

- Блок «Вложения»: перетаскивание, кнопка «Прикрепить файл», вставка из буфера (Ctrl+V) на странице тикета, прогресс с отметкой «продолжено после обрыва».
- Превью картинок и видео, скачивание, удаление, «Вставить в описание».
- В описании и комментарии можно вставить или перетащить файл прямо в поле: он загрузится, и на месте курсора появится `![имя](/api/v1/attachments/…)`.
- В тексте показываются картинкой или видео только наши адреса `/api/v1/attachments/…`: внешние картинки не грузятся (R-3.2).

## Последствия

- Резервные копии (R-3.1, раздел 4) должны включать каталог вложений. Это задача развёртывания — YT-30 и инструкция по восстановлению.
- Удалённое вложение удаляется с диска сразу. Когда появится корзина (YT-14), вложения будут уходить в неё вместе с тикетом.
- Документы Office проверяются только по сигнатуре zip, без разбора содержимого. Антивирус в MVP не входит.
- Лимит на пространство общий для всех пространств; отдельные лимиты для разных пространств можно добавить без смены модели.
