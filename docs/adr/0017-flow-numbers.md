# 0017. Номер в потоке: путь в дереве, пересчёт при вставке, номер на каждый путь

- Статус: принято, 2026-11-18
- Требования: R-2.9 (номер в потоке), R-2.6 (ссылки только по ключу), R-2.17 (недоступные не раскрываются), R-3.4 (пересчёт ≤ 2 с на 1 000 тикетов); карточка YT-11. Смежные: YT-09 (дерево, ADR 0015), карточка доски (номер на карточке доски)

## Решение

**Номер** — путь от верхнего предка: позиция на каждом уровне, через точку (1.3.2).

- Позиция у родителя — порядок детей (`ticket_parents.position`), его меняют перетаскиванием в дереве и вставкой «перед».
- Верхние тикеты — тикеты без родителя — нумеруются ручным порядком в своём пространстве (`tickets.root_position`). До первой перестановки это порядок создания.
- У тикета с несколькими родителями — номер на каждый путь: «№ 1.3 в AOS-201», «№ 2.1 в AOS-230».

**Хранение** — `ticket_numbers`: номер, прямой родитель на пути и ключ сортировки с выравниванием частей, чтобы 1.10 шло после 1.9. Номера хранятся, а не считаются при чтении: карточка, связи, дерево и список читают их одним запросом.

**Пересчёт** — в той же транзакции, что и операция:

- создание, в том числе «+ ребёнок» с местом «перед …»;
- добавление и снятие родителя;
- перенос и смена порядка;
- «обернуть»;
- перестановка верхних тикетов.

Как идёт пересчёт:

- Пересчитываются только затронутые ветки: все дети затронутых родителей и их потомки; верхние тикеты пространства — только если поменялся состав верхнего уровня.
- Номера считаются сверху вниз (родители раньше детей) в памяти, потом записываются только изменившиеся.
- Удаление тикета в корзину (YT-14) вызовет тот же пересчёт.

**История.** Каждый тикет, чей номер изменился, получает системную строку «Номер 1.3 → 1.4, вставлен AOS-…» (`source = system`, `source_detail = number:<inserted|moved|removed>:<ключ>`). У самого вставленного или перенесённого тикета такой строки нет: у него уже есть запись о связи. Уведомлений нет (R-2.9; уведомления — YT-18).

**Ссылки — только по ключу** (R-2.6). Номер нигде не служит адресом: ни в API, ни в упоминаниях, ни в URL.

**Видимость.** Номер показывается и для недоступного родителя, но без его ключа: «№ 1.1» вместо «№ 1.1 в AOS-…» (R-2.17).

**Где виден номер:**

- шапка карточки — все номера с родителем;
- блок «Связи» — «номер здесь» на каждой связи;
- дерево — номер того пути, под которым стоит строка;
- список пространства — с порядком «По потоку».

**Первое заполнение.** После миграции номера проставляются при старте сервера, без записей в историю.

## Последствия

- Номер на карточке доски появится вместе с доской: API уже отдаёт номера в списке (`numbers`).
- Перестановка верхнего уровня большого пространства пересчитывает всё пространство. Тест «вставка в начало дерева из 1 011 тикетов» укладывается в 2 с. Если пространство вырастет на порядок, можно будет считать только сдвинутый хвост.
- Номер не передаёт порядок между разными ветками: его задают связи «блокирует» (YT-12) и Гант (R-2.9).
