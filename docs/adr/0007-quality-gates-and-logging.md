# 0007. Журналирование ошибок и автопроверки

- Статус: принято, 2026-11-16
- Требования: карточка, п. 5

## Решение

**Журналирование.** Структурированные JSON-логи pino (встроены в Fastify), уровень — `YOURTASK_LOG_LEVEL`.
У каждого запроса `requestId` (заголовок `x-request-id`, поле в ошибке). Ошибки 5xx пишутся с трассировкой уровнем `error`, отказы 4xx — `info`.
Cookie, CSRF и `Authorization` вырезаются; query string в логах не пишется (там бывают одноразовые коды входа).
Ошибки браузера (`window.onerror`, необработанные промисы) отправляются на `POST /api/v1/client-errors` и попадают в тот же журнал.

**Автопроверки** — GitHub Actions (`.github/workflows/ci.yml`) на каждый push и pull request:
формат (Prettier) → линтер (ESLint) → типы (tsc strict) → тесты API и интерфейса (Vitest) → сборка → двойное применение миграций → e2e (Playwright) → сборка и запуск Docker-образа.
Локально то же самое — `npm run check` и `npm run test:e2e`.

## Последствия

- Изменение, ломающее любую проверку, не сливается (включить branch protection на `main`).
