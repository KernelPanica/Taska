# 0021. TQL: один разборщик, чипы и текст без потерь, полнотекст, сохранённые фильтры

- Статус: принято, 2026-11-19
- Требования: R-2.28 (TQL), R-5.3 (справочник), R-3.4 (поиск и TQL ≤ 1 с на 100 000 тикетов), R-2.20 (права и «Режим показа»), R-2.11 (архив скрыт), R-0.2/R-3.3 (понятные ошибки); карточка YT-15

## Решение

**Один разборщик — в `packages/contracts/src/tql.ts`.** Его используют и сервер, и интерфейс. Модуль даёт:

- лексер;
- парсер в дерево (`cond`, `pred`, `and`, `or`, `not`, `group`, `order by`);
- каталог полей и функций R-5.3 с допустимыми операторами;
- канонический вывод текста `printTql`;
- автодополнение `completeTql`.

Доски, правила, подписки и помощник подключатся к нему же.

- Ключевые слова — без учёта регистра. Поля, функции и ключевые слова — только английские.
- Значение — системное имя латиницей (`GD`) или отображаемое имя в кавычках (`"ГД"`). Кириллица без кавычек — ошибка `unquoted_text` с готовой подсказкой.
- У команд и колодцев появилось системное имя `key` (латиницей, уникально). Админ задаёт его в карточке группы. Без него значение пишут отображаемым именем в кавычках.
- Ошибка — `TqlProblem`: код, место `[start, end)`, что встретилось, подсказка «может быть, …» по расстоянию Левенштейна. Интерфейс переводит по коду (RU/EN) и подсвечивает место волнистой линией. Сервер отвечает `400 tql_invalid` с тем же объектом.

**Чипы и текст — два вида одного дерева.**

- Чипы — это группы «и/или», внутри — условия «поле → оператор → значение» и функции-условия. Вложенная группа — скобки, флажок «не» — `not`.
- Чипы → текст — это `printTql`; текст → чипы — разбор.
- Вывод канонический, а скобки и отрицания сохраняются как узлы дерева. Поэтому «чипы → текст → чипы» даёт то же дерево; это проверяют автотесты.
- Текст с ошибкой в чипы не переключается: интерфейс просит сначала исправить ошибку.

**Исполнение — SQL по таблице тикетов** (`apps/api/src/tickets/tql.ts`), затем права:

- Дерево превращается в `WHERE` с параметрами. Значения разрешаются по системному имени, отображаемому имени (кириллица сравнивается без учёта регистра) или id; неизвестное — `unknown_value`.
- Поля с несколькими значениями (стрим, исполнители, свои поля) сравниваются через `json_each`. `=` и `in` значат «среди значений есть», `!=` и `not in` — «нет среди значений», включая пустые.
- Найденные тикеты проходят ту же проверку прав, что и карточка (`access.evaluateMany`). Скрытые не попадают ни в выдачу, ни в `total`.
- Тикет «только заголовок» по условиям не находится: иначе запрос раскрыл бы его поля. В списке пространства без запроса он по-прежнему виден.
- Условие на поле под маской исключает тикеты, где поле скрыто от зрителя.
- «Режим показа» и «Смотреть как» работают сами: сервер считает права глазами линзы.
- Архив скрыт, пока запрос не упоминает `archived`.

**Поля и функции** — как в R-5.3:

| Поле                                                                                             | Как считается                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `zone`                                                                                           | Стартовое дерево зон R-5.1 по имени статуса (`Delivery` включает To Do, проработку, производство и тест). Когда зоны станут настраиваемыми, поменяется только этот источник. |
| `involvedTeams`                                                                                  | Команды детей плюс значение `involvedTeams`, если оно задано вручную (R-2.29).                                                                                               |
| `due`                                                                                            | Поле «Срок», а если его нет — дата окончания.                                                                                                                                |
| `estimate`                                                                                       | Поле «Размер».                                                                                                                                                               |
| `reporter`                                                                                       | Автор тикета.                                                                                                                                                                |
| `priority = Urgent`                                                                              | Синоним высшего приоритета; русские подписи тоже понимаются.                                                                                                                 |
| `actualStart`, `actualEnd`, `dueShifts`                                                          | Из истории статусов и сроков.                                                                                                                                                |
| `coordinator`, `owner`, `rework`, `foundIn`, `bugDecision`, `reworkRounds`, `fixState`, `tenure` | Читаются по системному имени из значений тикета. Пока их карточки (R-2.29, R-2.30, R-2.34) не сделаны, значения пусты; `is empty` работает.                                  |
| Любое своё поле типа                                                                             | По системному имени. Варианты списка и шкалы — по подписи.                                                                                                                   |

Функции:

- `me()`, `myTeams()`, `myGuilds()`, `today()`, `startOfWeek()` (понедельник), `daysAgo(n)`;
- `childrenOf`, `parentsOf`, `branch` (сам тикет и вся ветка), `linkedTo(KEY[, type])`, `causedBy`;
- `parentTrace` — из YT-14, теперь через общий разборщик;
- `overloaded()` разбирается, но отвечает `not_available` до YT-19.

Даты сравниваются по дню UTC.

**Полнотекст** (`text ~ "…"` или просто слова в строке поиска) использует FTS5 с триграммами:

- подстрока без учёта регистра, кириллица тоже; «ё» приравнена к «е»;
- ищет по ключу, названию, описанию и старому номеру (`ticket_text`) и по комментариям (`comment_text`, удалённые не ищутся);
- индекс ведут триггеры базы, поэтому любой путь изменения тикета или комментария его обновляет;
- короче трёх букв — поиск подстроки по ключу, названию и старому номеру.

Строка поиска: если текст разбирается как TQL — это запрос. Простые слова без операторов — полнотекст. Сломанный запрос остаётся ошибкой, а не превращается в поиск слов. Строка поиска списка пространства и Ctrl+K идут через тот же разборщик.

**Старый номер** — колонка `tickets.legacy_number`, поле `legacyNumber` в карточке. Через API оно только читается, заполняет его импорт (YT-29).

**Сохранённые фильтры** (`saved_filters`):

- Личный видит только автор.
- Общий принадлежит пространству и виден всем, кто видит пространство.
- Сохранить общий может тот, у кого в пространстве есть право «Настраивать доски пространства» (R-5.2: админ, ПМ, лид; у участника нет).
- Править или удалять — автор, админ пространства или суперадмин.
- Запрос сохраняется в каноническом виде; сломанный не сохраняется.

**Ctrl+K** — командная строка из любого места:

- ключ, слова или запрос;
- ↑↓ выбирают, Enter открывает тикет;
- «Все результаты» ведёт на страницу поиска с конструктором.

## Скорость (R-3.4)

Автотест `tql-load.test.ts` заводит 100 000 тикетов и ищет глазами участника, проверяя права каждого найденного:

| Запрос                                        | Время   | Найдено |
| --------------------------------------------- | ------- | ------- |
| Полнотекст «камера»                           | ≈110 мс | 10 000  |
| `assignee = me() and statusCategory = active` | ≈130 мс | 8 572   |
| Доска Жаб                                     | ≈330 мс | 33 333  |
| Сортировка по 37 000                          | ≈340 мс | 37 143  |
| `stream = GD or assignee.guild = GD`          | ≈600 мс | 66 667  |

Порог теста — 1 с. Самое дорогое — проверка прав на десятки тысяч найденных. Если выборки вырастут, следующий шаг — предварительный фильтр прав в SQL для простых выдач («всё пространство»).

## Ограничения

- `zone` — стартовое дерево R-5.1, пока зоны не настраиваются (R-2.19).
- Ошибка неизвестного значения приходит с сервера без позиции. Интерфейс находит слово в тексте сам.
- Ограничение сравнения дат по UTC: для команды в одном часовом поясе разница — максимум в начале суток.
